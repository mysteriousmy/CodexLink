# 实施计划

按可验证的闭环实施，不先建立一堆无人使用的抽象、接口或平台模板。当前已实现 P1–P3 的主要能力并产出 Linux AOT、Web 和个人签名 Android APK；以下按实际证据标注，外网/真机条件仍单列。详细结果见 [验收记录](verification.md)。

## P0：规划与可行性

- [x] 建立同仓库的 `server/`、`client/`、`docs/`、`deploy/` 目录。
- [x] 写入 AGENTS.md：性能优先、简洁工程、基本安全、AOT、无业务数据库、断线语义。
- [x] 确认首个服务端运行目标为当前 Linux x64。
- [x] 确定 Flutter App/Web + .NET 10 + Codex app-server 技术边界。
- [x] 验证 .NET 10 临时 AOT 探针的 HTTP、WebSocket、Codex 子进程调用。
- [x] 核对 AotAnywhere，验证 Linux → Windows x64 的探针交叉编译。
- [x] 核对本机 Codex schema 的附件输入、steer、Goal、Token 与账号额度接口。
- [x] 明确 App/Web 功能一致性、Material 3 布局和用量统计口径。

P0 不包含：真实 Codex 任务、多端业务实现、外网接入配置、实际服务安装、Windows/iOS 真机验收。

## P1：最小可运行闭环

交付：电脑启动网关，浏览器或 Android 连接后能创建一个会话、发送文本、看到流式回复并停止任务。

- [x] 建立一个 `net10.0` Minimal API 项目，启用 Native AOT、JSON 源生成，引用固定版本 AotAnywhere。
- [x] 建立一个 Flutter 工程，生成 Android/iOS/Web 平台目录；先验证 Android 和 Web。
- [x] 建立 Material 3 明暗主题、手机/宽屏布局与会话输入区，后续功能沿用同一设计。
- [x] 实现最小鉴权、项目配置、连接诊断；网页同源，原生客户端使用自己的访问令牌。
- [x] 实现 Codex 进程启动、握手、异步 stdio、RPC 关联与进程退出处理。
- [x] 打通线程创建/列表/有限历史、文本发送、事件增量和显式中断。
- [x] 完成最小审批卡片，支持同意/拒绝；不通过关闭审批绕过流程。
- [x] 先以协议替身验收，再在专用临时项目做一次真实 Codex 回合。
- [x] 发布并运行真实服务端 `linux-x64` AOT 产物，不以 `dotnet run` 替代发布验证。

验收：手机与网页看到相同 thread/turn，连续多轮不串线；响应失败能显示原因；CLI 未登录/未安装能被准确诊断。HTTP 发送响应只代表受理，任务完成以 Codex 事件为准。

## P2：连接可靠性

实现：心跳、重放、快照同步和前台恢复，已提交任务不会因 UI 消失被取消。弱网/蜂窝与长时间后台的实机验收仍待部署环境。

- [x] 心跳、前后台恢复、有限退避与鉴权失效处理。
- [x] 事件 epoch/seq、有界重放、缓存缺失后的快照同步。
- [x] 同一 requestId 去重；超时与网关重启后的不确定结果不能自动重执行。
- [x] 多设备订阅与审批首个决定生效，慢客户端不阻塞正常客户端。
- [x] 限制在途 RPC、事件缓存与队列容量，清理连接与取消注册。
- [x] 验证 Codex 退出、网关重启、断网时的真实状态与恢复提示。

关键验收：发送前断网、发送已受理但响应丢失、输出中断网、Wi-Fi/蜂窝切换、长时间后台、审批期间断网、客户端过慢、Codex 进程退出。

恢复时先订阅/缓存事件再读取快照，验证正在结束的轮次没有丢失或重复。只有该阶段通过，才把“稳定远程使用”标为完成。

## 检查约定

- 后端修改：相关 build、核心行为测试、阶段性 AOT publish 与运行检查；新增依赖/序列化/运行时行为后必须补 AOT 验证。
- Flutter 修改：format、analyze、相关行为/Widget 测试；页面变化再验证实际尺寸、软键盘与运行状态。
- 协议/可靠性测试优先用替身进程与事件回放，不以反复调用真实模型作为默认测试方式。
- 当前采用 Python 黑盒契约测试 + 独立 stdio 协议替身，直接覆盖 Managed 与 AOT 二进制；没有为测试复制生产实现。客户端使用 Flutter 单元与 Widget 测试。
- 没有应用代码时只做文档、配置与链接一致性检查，不编写没有业务意义的占位测试。

## 仍需部署时落实的条件

服务端首发 Linux 已确定。外网入口、手机系统与 iOS 签名环境尚未确认，按默认先 Android/Web 与私网入口的方案准备，但不安装网络工具或创建公网服务。最终外网可靠性必须用用户实际手机网络验证，CLI 架构本身无法消除电脑断网或休眠。

## 本次验收边界

服务端协议、连接、附件、steer、Goal 和统计已通过替身测试及少量真实 Codex 任务。Android 发布 APK 在只读模拟器验证登录、系统文件选择、上传、真实消息与安全凭据恢复；Web 验证文件选择/拖放/预览、明暗主题和手机/宽屏。尚未具备实际手机蜂窝入口、iOS 签名环境，也未完成两小时连续负载和真机帧时间测量，不能把这些勾选为通过。
