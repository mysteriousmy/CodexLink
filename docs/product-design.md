# 产品与界面设计

设计基线：2026-10-23。以下是首版需求及实现约定；当前代码和验证状态见 [验收记录](verification.md)。Flutter App 与 Web 共用功能与状态模型，Android/Web 先验收，iOS 随平台构建补齐验证。

## 1. 首版必须交付

| 能力 | 用户能完成的操作 |
| --- | --- |
| 对话 | 全部本机会话列表、目录/搜索/归档筛选、活跃状态同步、历史、Markdown、代码、工具进度、Diff、审批、停止 |
| 指令 | `/skills` 原生技能选择、`@文件` 搜索并引用、`/mcp` 实际目录、`/goal` 原生目标编辑器 |

不同实施阶段是交付顺序，不代表将附件、steer、Goal 或用量移出首版。

## 2. Material 3 视觉方向

采用 Flutter 原生 Material 3 组件与主题系统。以低饱和中性色表面、靛蓝主色和明确的状态色形成层级，初始种子色为 `#5865D8`，通过 `ColorScheme.fromSeed` 生成明暗配色。可读性与状态辨识优先于装饰。

- 采用统一的 4/8 dp 间距节奏；主要卡片和输入区圆角约 16–24 dp，不给每条工具日志都包一层卡片。
- 消息正文使用可缩放的 16 sp 基准和舒适行距，代码采用系统可用等宽字体；不为装饰字体增加 Web 首屏下载成本。实际网络验收发现 Google Fonts 回退超时，因此必要的中文/等宽字体随 Web 提供并缓存；这是中文可用性的成本，见验收记录。
- 用 Material 3 的 surface 层级、细分隔线和少量 elevation 区分区域，避免大面积模糊、玻璃效果和持续动画。
- 操作触达区域至少 48 dp；图标提供语义标签/Tooltip，状态同时有文字，不只用颜色表达。
- 支持系统字体缩放、键盘焦点、屏幕阅读和减少动画偏好。进度条更新不不断触发整页朗读。

这是项目的初始视觉方案；布局和颜色由主题集中管理，不在各个 Widget 中散落硬编码。

## 3. 页面布局与信息位置

按可用宽度划分布局，初始断点为 600 / 960 logical pixels，实施时用真实内容和键盘验证。

| 宽度 | 布局 |
| --- | --- |
| < 600 | 会话列表与详情分页面；详情顶部显示标题/连接状态，账号用量与详细指标用底部面板 |
| 600–959 | 可切换列表与会话；正文优先，详细工具/用量按需展开 |
| ≥ 960 | 约 280 dp 会话侧栏 + 主会话区；正文最大阅读宽度约 900 dp，宽余区域按需显示详情 |

宽屏示意（仅示意布局，数字不是用户真实用量）：

│ 项目选择           ├────────────────────────────────────────────────┤
│                    │                                                │
│ 最近会话           │ 已用 18K / 80K Token · 12 分钟                 │
│ · 修复连接         ├────────────────────────────────────────────────┤
│ · 开发新功能       │ 用户消息 / 附件                                │
│ · 项目说明         │ Agent 回复                                     │
│                    │   工具调用摘要 [展开]                           │

│ 累计 12.8M         │ 补充当前任务…                                  │
│ 5h / Weekly 条形图 │ [+ 文件]        [停止]       [补充指令 Steer]  │

手机详情页保留标题、连接指示、可点击的简短用量条、输入框上方的紧凑 Goal 栏、消息和输入区。今日/累计与配额放在顶部账号入口的底部面板中，会话列表页只保留一行账号入口，完整统计按需展开。输入法弹出时输入区跟随安全区上移，不把统计卡片挤到消息正文中。

- **用量条**：默认显示“会话 128K · 上下文约 37%”；点击后展示窗口大小、已用 Token、输入/输出/缓存拆分和数据时间。
- **Goal 栏**：仅未完成目标显示在输入框上方，展示简短目标、状态与预算；点击弹窗查看完整内容，右侧提供无文字的编辑、继续/暂停、删除图标。完成的历史目标默认隐藏。输入框内旗帜切换目标模式，当前文字成为待提交目标，发送才启动，再次点击取消；不弹目标设置窗口。侧栏“新建 Goal”和 /goal 也进入此输入方式。编辑已有目标仍使用简栏的编辑图标。
- **账号面板**：账号标识、今日 Token、累计 Token、存在的额度条、重置时间和刷新时间。额度条固定标“已用”，不在页面间交替使用“剩余”。
- **状态与中途回复**：commentary 与 final_answer 都显示；提交、执行、回复、工具、等待审批各自按真实事件呈现，使用短切换动画，不显示虚假进度百分比。
- **工具与审批**：工具默认摘要，输出按需展开；审批保持醒目且不会自动滚出可操作区域。
- **项目与目录**：新建会话读取 Codex 原生项目，可同步创建项目；目录选择器读取主机目录，支持逐级进入、返回、搜索、创建文件夹和确认工作目录。
- **Diff**：中途 fileChange 与最终轮次摘要均显示彩色文件列表、增删统计与类型；文件点击打开全屏 Diff，区分增删/上下文/块头，支持行号、换行与复制。
- **刷新与分页**：会话列表顶部下拉刷新，空列表/短列表同样可用；刷新保留搜索、项目/归档筛选、当前会话和草稿，失败保留旧列表并允许重试。会话列表靠近底部自动加载下一页；历史消息靠近顶部自动加载更早内容，插入历史时保持当前可见内容的位置。
- **任务通知**：手机列表更多菜单、桌面侧栏通知图标打开设置，避免挤占会话列表。Android 开启后展示常驻连接提示，用户可关闭；网页无权限时使用最多三条、可关闭的右上角气泡。通知不包含正文，完成一轮不宣称 Goal 已达成。旧网关明确要求升级。
- **阅读与输入**：用户上滑阅读时停止自动滚底，显示“有新内容”；回到底部后恢复跟随。桌面默认 Enter 发送、Shift+Enter 换行，输入法组合输入不触发发送；手机使用明确的发送按钮。

## 4. 文件上传与消息绑定

首版接受普通文件，不把“附件”限制成图片。文件选择是跨平台边界：App 走系统选择器，Web 支持文件选择和桌面拖放；图片粘贴可复用同一流程。

流程：选择 → 展示附件条 → 流式上传 → 服务器返回附件 ID → 与正文一起提交 `turn/start` 或 `turn/steer`。附件有“上传中、可发送、失败、已提交”状态，支持取消、移除和重试。未上传完成的附件不随发送按钮被静默跳过，发送须等待完成或由用户移除失败项。

服务端保存随机 ID 对应的文件和小型 JSON 元数据：原始名称、大小、内容类型、项目/线程归属、创建时间和是否已引用。原始文件名只做显示用途，落盘路径不由客户端指定。上传成功仅代表文件就绪；消息需要收到操作受理结果后才标已提交，执行结果仍以 Codex 事件为准。

### 给 Codex 的输入

- 支持的图片使用 app-server `localImage` 输入，路径指向主机上的已上传文件；只把校验通过的图片交给图片解码流程。
- 普通文件通过文本输入附带服务器生成的文件清单与可读绝对路径，让 Codex 使用文件/工具能力读取。用明确的数据块转义名称与路径，不拼 shell 命令，不把文件名当指令执行。
- 本地 `UserInput` schema 没有通用二进制 `file` 类型；不能将其他模型 API 的文件输入能力当成本协议已支持。`mention` 主要有应用引用用途，未验证前不借用它冒充普通文件附件。
- 上传目录必须在该会话 Codex 沙箱的允许读取范围；适配现有沙箱策略，只添加必要目录，不为附件关闭沙箱。使用严格只读策略时同步验证可读性。
- PDF、Office、压缩包等文件能上传，不保证每种格式都被模型直接理解；由 Codex 使用已具备的工具处理。界面分别展示“已上传”和实际处理结果，不做全能文档解析平台。

### 容量与保留

初始可配置上限：单文件 25 MiB、单条消息最多 10 个附件且总计 100 MiB、服务端附件总量 1 GiB。上传中也计入容量预留，超额明确拒绝；不把整个文件读进托管内存，不在 JSON 中携带 Base64。

未提交的上传保留 24 小时，超时或取消后清理临时文件。已被消息引用的附件保留至用户显式清理，受总量硬上限约束；不为腾空间静默删除历史引用。清理提示哪些附件会失效，当前活动任务/Goal 使用的附件不允许清理；失效附件在历史中标记不可用。退出后清理不完整临时文件可在下次启动完成。

下载接口鉴权并绑定附件 ID，默认 `Content-Disposition: attachment`；不以内联 HTML/SVG 等主动内容作为普通预览。未请求时不自动解压、执行上传文件。新会话可先创建空线程再上传，以简化归属和重连恢复。

## 5. Steer 与 Goal 的行为

### Steer

任务空闲时按钮为“发送”；正在执行时变成“补充指令”，调用 `turn/steer`，携带 `expectedTurnId`。文字与附件走同一输入构建逻辑。输入仍处于当前轮次，不能实现成“停止旧任务 + 新开任务”。

若用户编辑期间轮次结束或变化，服务器返回冲突；保留正文和附件，提示当前任务已结束，由用户重新选择发送，不自动提交新轮次。steer 不携带模型/工作目录/沙箱等轮次级配置覆盖。停止按钮独立存在，显式调用 interrupt。

### Goal

使用 Codex 原生 `thread/goal/set`、`get`、`clear` 与更新事件；状态和持续推进由 Codex 管理，网关不再实现第二套自动调度器。

- 创建目标时填写 objective，可选择 Token 预算。未设预算即显示“未设上限”，不伪造默认预算。
- 展示 `active`、`paused`、`blocked`、`usageLimited`、`budgetLimited`、`complete` 对应的中文状态，以及 `tokensUsed` / `timeUsedSeconds`。
- 用户可暂停/恢复、调整预算、清除目标；显式操作携带 `origin: user`。前端不自行把失败任务标完成，也不自动解除暂停或预算限制。
- 暂停/清除 Goal 与中断当前轮次是不同动作。“停止”在启用 Goal 时明确提供“停止当前轮次并暂停目标”，分别执行并核实结果，避免用户停止后 Goal 又自动继续。
- 新目标会重置该 Goal 的用量；相同未终结目标的状态/预算调整保留用量。界面在替换目标时说明重置影响。
- 目标文本非空、最多 4,000 字符；可选预算必须是有效正整数。更新预算时区分“未修改”与“明确移除预算”，DTO 不能把两种情况都序列化成 null。

断线时继续遵守 Codex 的 Goal/任务状态，重连调用 `get` 恢复。Goal 消耗不等同于整段会话消耗，不能混用一个进度条。

## 6. 会话 Token 与上下文

以 CLI `0.163.0` 生成的 `ThreadTokenUsageUpdatedNotification` 为实现基线：`threadId`、`turnId`、`tokenUsage.total`、`tokenUsage.last`、可空 `modelContextWindow`。

| 指标 | 来源与口径 |
| --- | --- |
| 会话累计 Token | `tokenUsage.total.totalTokens`；是快照，收到事件时替换，不能重复相加 |
| 输入 / 输出 | 对应 total 中的 `inputTokens` / `outputTokens` |
| 缓存输入 / 推理输出 | 使用官方对应字段，作为输入/输出的明细展示，不再次加到总量 |
| 上下文窗口 | `modelContextWindow`，使用该线程的报告值，不按模型名硬编码宣传规格 |
| 最近上下文占用 | `tokenUsage.last.totalTokens`，表示最近报告的活动上下文规模 |
| 已用百分比 | `clamp(last.totalTokens / modelContextWindow × 100, 0, 100)`，仅在窗口大于零且两项有效时计算 |

默认文案为“上下文约 37%”，详情注明“按最近一次 Codex 报告估算，含输入与输出”。这是原始窗口占比；Codex TUI 对用户可控剩余空间还有基线扣除算法，数字可能略有区别。本项目不硬编码其内部 12K 基线常量，也不使用会话累计 Token 除以窗口大小。

流式期间指标按最新事件更新，不声称每个新字符已计入。压缩上下文后允许占用下降，模型切换后使用新的报告窗口。数据为 null 或未到达时显示“待更新”，不得显示 0% 或固定窗口。点击指标可见完整整数，摘要用 K/M 缩写。

恢复读取历史时，优先使用官方 resume/通知可提供的用量。若协议不能恢复某项，不扫描私有 JSONL/SQLite，也不把所有历史文本重新分词冒充官方数值；展示待更新。`account/usage/read` 支持的线程估算是不同来源，若采用需明确标估算，不能拼成同一“精确累计”。实施阶段需用真实 CLI 验证 resume 的通知顺序与可恢复范围。

## 7. 当前账号的 Token 与额度

账号指**运行网关这台电脑当前 Codex 登录的账号**，不是 CodexLink 设备令牌，也不是仅由本客户端发起的任务集合。账号变化时清空旧账号快照，避免串号。

### 今日与累计 Token

优先使用 `account/usage/read`：累计值取 `summary.lifetimeTokens`，日值来自 `dailyUsageBuckets` 的 `startDate` / `tokens`。这是官方服务返回的账户统计，可能存在延迟；不通过本机线程求和重建“账号总量”。

“今日”日期以网关配置时区确定，默认首个 Linux 主机时区（当前 Asia/Shanghai），匹配对应 `startDate` 并显示该日期。官方公开 schema 未声明日桶时区，不能把日桶转算成北京时间 00:00–24:00 的精确总量：详情标“官方日统计，日期 YYYY-MM-DD；日界线未公开”。若当天桶尚未返回，显示“今日待更新”，可另外显示最近有数据的日期，但不能把昨日数字冒充今日。

字段 null、不支持的认证方式、接口暂时失败要区分。API-key-only 等未提供该统计时显示“当前登录方式未提供”，不自建数据库填数。明确返回的零可以显示 0，缺失值不能。

### 5h / Weekly

读取 `account/rateLimits/read`，消费 `account/rateLimits/updated`；优先使用 `rateLimitsByLimitId`，保留 limitId/名称，兼容单一 `rateLimits` 视图。

- 通过 `windowDurationMins == 300` 识别 5h，通过 `10080` 识别 weekly，不假设 primary 永远是 5h、secondary 永远是 weekly。
- 展示官方 `usedPercent` 与 `resetsAt`（Unix 秒），重置时间转换成设备时间并标明；不从 Token 数倒推出订阅额度。
- 某个账号/额度桶没有 5h 就不显示该行；weekly 同样只在可识别且有数据时展示。不同额度桶不能相加，默认突出通用 Codex 桶，其余在展开详情中显示。
- 暂时读取失败与“本来没有该窗口”不同：有旧值时标更新时间/已过期，不能把错误造成的缺失当作新配额为零。
- 时间走到 resetsAt 仅触发重新读取，不自行将用量清零或推断账号一定已经恢复可用。

### 更新与缓存

会话用量/Goal 以事件更新。账号用量在连接建立、打开面板、回到前台和任务完成时按需刷新，提供手动刷新；网关合并并发读取，初始缓存有效期 60 秒。额度事件可立即更新。没有订阅设备时不持续轮询，每个 Flutter 页面也不各建一个计时器。

## 8. 验收要点

- App/Web 均验证普通文件和图片，失败重试/取消，包含中文或特殊字符的名称，大文件限制，以及“上传成功但消息提交失败”。
- 附件随普通消息和 steer 可被 Codex 在其沙箱内读取；重连后仍能识别附件，清理后的缺失状态明确。
- steer 与轮次结束竞态、重复请求、网络响应丢失不产生额外轮次。
- Goal 创建/修改预算/移除预算/暂停/恢复/清除、多端更新、重连恢复和停止后不意外自动继续。
- Token 快照重复到达不叠加；上下文压缩后进度下降；窗口未知不除零；缓存明细不重复计数。
- 用量数据覆盖真实零、null、缺日桶、跨午夜、切换账号、缺失 5h、多个额度桶、读取失败和重置时刻。
- 明暗主题分别检查手机/宽屏、字体放大、键盘、长路径/代码、上传与流式输出同时发生时的帧时间。

## 9. 核对依据
